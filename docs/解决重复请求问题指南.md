# 重复请求问题分析与解决方案

## 🔍 问题现象

在开发者工具的 Network 面板中观察到：

- 同一个 API 请求会被发起 2 次
- 第一次请求通常会失败或返回错误
- 第二次请求成功返回数据

## 🎯 根本原因分析

### 1. SSR + CSR 双重数据获取

```typescript
// ❌ 问题代码：在 SSR 和 CSR 阶段都会执行请求
const { data } = useAsyncData('products', async () => {
  // SSR 阶段执行一次
  return await itemApi.getList(params)
})

onMounted(async () => {
  // 客户端挂载时又执行一次！
  if (!data.value) {
    await loadProducts()
  }
})
```

### 2. 缓存策略不当

```typescript
// ❌ 问题代码：禁用缓存导致重复请求
return useHttp('/goods/items', {
  cache: 'no-cache', // 每次都重新请求
  server: true,
})
```

### 3. useFetch 的水合 (Hydration) 问题

- **第一次请求**：SSR 阶段在服务端执行
- **第二次请求**：客户端水合时重新验证数据

### 4. 组件重复挂载或状态变化

- 路由变化触发组件重新挂载
- 响应式状态变化触发重新请求

## 🛠️ 解决方案

### 方案1：优化缓存策略

```typescript
// ✅ 解决方案：合理设置缓存
export function useItemApi() {
  return {
    getList(params: IItemListParams) {
      return useHttp<IItemListApiResponse>('/goods/items', {
        query: params,
        server: true,
        // 允许缓存以避免重复请求
        cache: 'default',
        // 为每个不同的参数组合生成唯一的缓存键
        key: `items-${JSON.stringify(params)}`,
      })
    },
  }
}
```

### 方案2：创建防重复请求的 Composable

```typescript
// composables/useDataFetch.ts
export function useDataFetch<T>(
  key: string,
  fetcher: () => Promise<T>,
  options: {
    watch?: any[]
    default?: () => T
    server?: boolean
    client?: boolean
  } = {}
) {
  return useLazyAsyncData(key, fetcher, {
    ...options,
    // 关键配置：避免客户端重新请求已有的服务端数据
    getCachedData(key) {
      const nuxtApp = useNuxtApp()
      return nuxtApp.ssrContext?.cache?.[key] ?? nuxtApp.payload.data[key]
    },
  })
}
```

### 方案3：商品列表专用的数据获取 Composable

```typescript
export function useItemListData(getParams: () => any, options: { watchQuery?: boolean } = {}) {
  const route = useRoute()
  const { getList } = useItemApi()

  return useDataFetch(
    `item-list-${JSON.stringify(getParams())}`,
    async () => {
      const response = await getList(getParams())
      return response.data.value?.data
    },
    {
      watch: options.watchQuery
        ? [
            () => route.query.brand_id,
            () => route.query.sort,
            // ...其他查询参数
          ]
        : [],
      server: true,
      client: false, // 关键：避免客户端重复请求
    }
  )
}
```

### 方案4：优化页面组件结构

```vue
<script setup lang="ts">
// ✅ 使用优化的数据获取方式
const { data, pending, error, refresh } = await useItemListData(() => getApiParams(1), {
  watchQuery: true,
})

// 处理数据更新（不会触发重复请求）
watchEffect(() => {
  if (data.value) {
    // 处理数据变换和状态更新
    updateProductList(data.value)
  }
})
</script>
```

## 📋 最佳实践

### 1. 使用合适的缓存策略

- **商品列表**：`cache: 'default'` + 唯一缓存键
- **商品详情**：`cache: 'default'` + 较长缓存时间
- **用户相关数据**：`cache: 'no-cache'` 或 `cache: 'reload'`

### 2. 正确配置 SSR/CSR

```typescript
// 只在服务端获取数据，客户端复用
{
  server: true,
  client: false
}

// 服务端优先，客户端可重新验证
{
  server: true,
  client: true,
  getCachedData: (key) => { /* 缓存逻辑 */ }
}
```

### 3. 合理使用 useLazyAsyncData

```typescript
// ✅ 推荐：不阻塞页面导航
const { data, pending } = useLazyAsyncData(key, fetcher)

// ❌ 避免：阻塞页面导航
const { data, pending } = useAsyncData(key, fetcher)
```

### 4. 避免在 onMounted 中重复请求

```typescript
// ❌ 错误做法
onMounted(async () => {
  await loadData() // 可能与 SSR 数据重复
})

// ✅ 正确做法
watchEffect(() => {
  if (data.value) {
    // 基于已获取的数据进行处理
    processData(data.value)
  }
})
```

## 📊 性能影响

### 修复前

- ❌ 每次页面加载都会发起 2 次相同请求
- ❌ 增加服务器负载和响应时间
- ❌ 用户体验差（Loading 状态时间长）

### 修复后

- ✅ 每次页面加载只发起 1 次请求
- ✅ 合理利用缓存，减少服务器压力
- ✅ 更快的页面加载速度和更好的用户体验
